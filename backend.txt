2. ARCHITECTURE & DESIGN PRINCIPLES
================================================================================
HealthSync bridges 4 distinct clinical healthcare roles around ONE unified, sovereign
patient record:

   +-----------------------------------------------------------------------+
   |                       ONE UNIFIED PATIENT RECORD                      |
   |              (Identified by unique ID: e.g. ML-PAT-1001)              |
   +-----------------------------------------------------------------------+
        ^                       ^                     ^                 ^
        |                       |                     |                 |
  [ Hospital Desk ]      [ Doctor Portal ]     [ Patient Portal ]  [ Pharmacy ]
  - Patient Registration - Clinical Queue      - Health Profile    - Live Queue
  - Unique QR Hash       - Vitals & Diagnosis  - Dynamic Charts    - Prep / Ready
  - Roster & Doctors     - Rx Builder & OCR    - Privacy Center    - Token # Gen
  - Appointment Booking  - 2nd Opinion Request - Smart Reminders   - Stock Toggles

Design Tenets:
1. Zero-Friction Startup: The application boots instantly with `uvicorn backend.main:app`
   without demanding an active MySQL daemon on port 3306.
2. Consent-Aware Access: Patient data is never exposed without either an active scheduled
   appointment or explicit patient consent (approved Access Request).
3. Immutable Audit Logging: Every view, appointment booking, prescription generation,
   and consent grant/revocation is logged with actor name, role, timestamp, and IP.
4. Auto-Dispatch Workflows: Saving a doctor consultation immediately pushes the e-prescription
   to the pharmacist's live dispensing queue. When the pharmacist marks it "Ready for Pickup",
   a pickup token is generated and the patient is automatically alerted.

3. DATABASE MODELS & SCHEMA (22 ENTITIES)
================================================================================
Located in `backend/models.py`, the database schema implements 22 relational entities:

1.  Role: System roles (HOSPITAL, DOCTOR, PATIENT, PHARMACIST).
2.  User: Master credentials, email, password_hash, full_name, phone, avatar_url.
3.  Hospital: Multi-hospital directory (Apollo, BMSCE, etc.) with emergency helplines.
4.  Doctor: Specialization, department, license number, consultation fee, duty status.
5.  Patient: Unique ID (`ML-PAT-XXXX`), date_of_birth, gender, blood_group, QR code hash.
6.  HealthProfile: Height, weight, allergies (JSON), chronic conditions (JSON), insurance.
7.  Pharmacist: License number, dispensing counter number (e.g. Counter 1 - FastTrack).
8.  Appointment: Linked hospital, doctor, patient, date, slot, reason, status.
9.  Consultation: Symptoms, diagnosis, vitals (JSON), shared notes, future doctor notes,
    private notes flag.
10. Prescription: Linked to consultation, status (`Sent`, `Preparing`, `Ready for Pickup`,
    `Dispensed`), pickup token, OCR raw text.
11. PrescriptionItem: Medicine name, dosage, frequency, duration, instructions, stock flag.
12. CustomRecordType: Patient-defined custom health tracking categories (e.g. Blood Sugar).
13. CustomRecordField: Field metadata for dynamic record types (name, type, unit).
14. CustomRecordEntry: Logged values (JSON) for dynamic charts over time.
15. Document: Uploaded scans, PDF reports, imaging with category and report date.
16. AccessRequest: Second opinion requests with status (`Pending`, `Approved`, `Denied`, `Revoked`),
    scope (`FULL`, `PRESCRIPTIONS_ONLY`, `LABS_ONLY`), and duration.
17. AuditLog: Immutable security log of all read/write operations on patient data.
18. Reminder: Smart reminders (sources: `APPOINTMENT`, `PRESCRIPTION`, `CONDITION_ENGINE`).
19. Notification: In-app notification center alerts.

4. DUAL-MODE DATABASE RESILIENCE
================================================================================
Located in `backend/database.py`:
- In production, set `DATABASE_URL=mysql+pymysql://user:pass@host:3306/healthsync_db`.
  The engine tests the connection on startup. If MySQL is unreachable, it logs a graceful
  warning and transparently falls back to local SQLite (`healthsync.db`).
- In development/demo, default execution creates and maintains `healthsync.db` locally.
- Tables are initialized automatically on startup via `Base.metadata.create_all(bind=engine)`.
- The database is auto-seeded with rich clinical data on first run.

================================================================================
5. PURE-PYTHON CRYPTOGRAPHY & AUTHENTICATION
================================================================================
Located in `backend/auth.py`:
- Standard libraries `hashlib`, `hmac`, `base64`, `json`, `secrets`, and `time` are used.
- Password Hashing: PBKDF2-HMAC-SHA256 with 100,000 iterations and a 16-byte random salt.
- JWT Tokens: Signed with HMAC-SHA256, base64url encoded header and payload, with standard
  `exp` and `iat` claims.
- Benefit: Completely immune to Python 3.13 deprecation of `passlib` or compilation issues
  with `cryptography` C-extensions.

6. PORTAL-BY-PORTAL FEATURE IMPLEMENTATION
================================================================================

6.1 HOSPITAL (ADMIN / RECEPTION) PORTAL:
- Dashboard KPIs (`GET /api/hospital/stats`):
  - Total appointments today, breakdown by status (Scheduled, In Progress, Completed).
  - Doctors on duty count.
  - Pending prescriptions count in the pharmacy.
  - Total registered patients and affiliated hospitals.
- Patient Directory & Search (`GET /api/hospital/patients?q=...`):
  - Multi-attribute search across Patient ID, full name, phone number, and email.
- Patient Registration (`POST /api/hospital/patients/register`):
  - Automatically issues a unique sequential Patient ID (`ML-PAT-1006`).
  - Generates a sovereign QR code hash token.
  - Simultaneously registers User, Patient, and HealthProfile records.
  - Automatically writes an immutable audit log entry.
- Multi-Hospital Doctor & Pharmacist Roster (`GET /api/hospital/doctors`, `GET /api/hospital/pharmacists`).
- Appointment Booking & Scheduling (`POST /api/hospital/appointments/book`):
  - Validates doctor and patient existence.
  - Prevents double-booking conflicts.
  - Auto-creates an appointment reminder for the patient.
- Contextual Appointment State Transitions (`PATCH /api/hospital/appointments/{id}/status`):
  - Scheduled -> In Progress -> Completed / Cancelled.

6.2 DOCTOR CLINICAL PORTAL:
- Today's Queue (`GET /api/doctor/queue`):
  - Lists today's queue of patients ordered by slot time.
  - Shows age, gender, blood group, allergies, and chronic conditions directly in the queue card.
- Comprehensive Patient Detail (`GET /api/doctor/patients/{id}`):
  - Full clinical profile, emergency contacts, BMI calculation, and consent authorization check.
- Longitudinal Medical Timeline (`GET /api/doctor/patients/{id}/timeline`):
  - Complete chronological visit history: past consultations, diagnoses, vitals,
    notes, and historical prescriptions.
  - Automatically logs a `VIEW_RECORD` audit event.
- Consultation & Prescription Builder (`POST /api/doctor/consultations`):
  - Records diagnosis, symptoms, and structured vitals (BP, Pulse, SpO2, Temp).
  - Dual notes architecture: "Shared Notes" (visible to patient) and "Future Doctor Notes"
    (clinical handoff notes for subsequent doctors), plus optional "Private Doctor Notes".
  - Multi-item prescription builder (Medicine Name, Dosage, Frequency, Duration, Instructions).
  - Auto-Dispatch: Immediately sends the prescription to the hospital pharmacy queue ("Sent").
  - Auto-Schedules: Generates active medicine reminders in the patient's portal.
- Second Opinion Consent Request (`POST /api/doctor/second-opinion/request`):
  - Allows an external specialist to request access to another hospital's patient record.
  - Record remains locked until the patient explicitly approves in their Privacy Center.

6.3 PATIENT HEALTH PORTAL & PRIVACY CENTER:
- Dashboard Overview (`GET /api/patient/{id}/dashboard`):
  - Highlights next upcoming appointment, active medications list, latest prescription
    dispensing status, and active reminders count.
- Personal Health Profile (`GET` & `PUT /api/patient/{id}/profile`):
  - View and edit height, weight, allergies, chronic conditions, insurance details.
- Real-Time Prescription Status Tracker (`GET /api/patient/{id}/prescriptions`):
  - Live progress stepper: Sent -> Preparing -> Ready for Pickup -> Dispensed.
  - Displays assigned pickup token number (e.g. `T-24`).
- Document Uploads & Lab Scans (`GET` & `POST /api/patient/{id}/documents`):
  - Manage diagnostic reports, imaging scans, and discharge summaries.
- Dynamic Custom Records Engine (`GET` & `POST /api/patient/{id}/records`):
  - "+ Add New Record Type": Patient can define custom health tracking categories (e.g. Blood Sugar,
    Blood Pressure, Thyroid, HbA1c) with custom fields.
  - Log numeric values over time with formatted data for interactive Recharts visualizations.
- Sovereign Privacy Center (`GET /api/patient/{id}/privacy`):
  - Incoming Access Requests: Pending requests from external doctors with purpose and scope.
  - Decision Controls (`POST /api/patient/privacy/decide`): Approve or Deny requests,
    with custom scope (`FULL`, `PRESCRIPTIONS_ONLY`, `LABS_ONLY`) and duration (24h, 7d, 30d).
  - Active Grants List: Shows all active doctor accesses with a one-click "Revoke" button.
  - Access Audit Trail: Real-time table showing who viewed what, at what time, and from what IP.
- Smart Reminders (`GET`, `POST`, `PATCH /api/patient/{id}/reminders`):
  - Rules-based automated schedules for appointments, prescriptions, and condition care.

6.4 PHARMACIST LIVE QUEUE & DISPENSING:
- Live Queue (`GET /api/pharmacist/queue`):
  - Real-time queue sorted newest-first with patient name, prescribing doctor, and medicine items.
- Status Progression & Token Generation (`PATCH /api/pharmacist/prescriptions/{id}/status`):
  - Sent -> Preparing -> Ready for Pickup -> Dispensed.
  - Transitioning to "Ready for Pickup" automatically generates a unique token (e.g. `T-24`)
    and dispatches an in-app notification to the patient.
- Stock-Out Flagging (`PATCH /api/pharmacist/prescriptions/{id}/stock-out`):
  - Mark specific medicines as out-of-stock, notifying attending physicians and patient.
- Dispensed History Archive (`GET /api/pharmacist/history`).

7. SIMULATED OCR PRESCRIPTION SCANNER
================================================================================
Endpoint: `POST /api/doctor/scan-prescription`
- Takes an uploaded prescription image or raw OCR text.
- Extracts structured clinical entities:
  - Diagnosis (e.g. "Coronary Artery Disease - Angina Prophylaxis")
  - Patient Vitals (BP, Pulse, SpO2, Temp)
  - Extracted Medicines (Name, Dosage, Frequency, Duration, Instructions)
  - Lifestyle / Dietary Advice
- Returns high-fidelity data that pre-fills the doctor's consultation builder for
  review and confirmation before saving.

8. SMART REMINDERS RULES ENGINE
================================================================================
The smart reminder engine maps clinical sources to actionable patient notifications:
1. Appointment Rules:
   - 24 hours prior to appointment: "Upcoming appointment with [Doctor] at [Hospital]".
   - 1 hour prior: "Check-in reminder for [Slot]".
2. Prescription Rules:
   - Active prescriptions automatically parse dosage frequency (e.g. "Twice daily")
     into daily morning/night intake reminders.
3. Condition-Based Clinical Rules:
   - Asthma: Post-inhaler lukewarm water rinse alerts.
   - Diabetes: Pre-breakfast fasting blood sugar checks; post-meal medication timing.
   - Hypertension: Daily 09:00 AM resting BP & pulse measurement alerts.
   - Renal / Kidney Stones: Hydration prompt every 2 hours.

9. SOVEREIGN CONSENT & AUDIT TRAIL ARCHITECTURE
================================================================================
HealthSync implements a sovereign consent model:
1. Consent Barrier: Doctors cannot browse patient records arbitrarily by ID. Access is only
   authorized if:
   a) The patient has an active appointment with that doctor.
   b) The patient has explicitly approved a Second Opinion Access Request.
2. Scope & Time-Bound Grants: Patients can restrict access scope to "Prescriptions Only"
   or "Lab Reports Only", and specify durations (24 Hours, 7 Days, 30 Days).
3. Instant Revocation: Patients can revoke access at any second via the Privacy Center.
4. Tamper-Evident Audit Logging: Every view and modification is written to `audit_logs`
   with actor identity, role, timestamp, action type, and client IP address.
